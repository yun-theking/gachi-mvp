# 2차 사용자 테스트 가이드

1차 피드백을 반영한 버전으로 같은 테스터분들께 다시 써보시게 할 때 쓰는 가이드예요.

## 테스트 전 준비 (운영자)

1. **AI 글 품질 먼저 확인:** AI 키가 있는 환경에서 `OPENAI_API_KEY=... npm run eval`을 돌려 `eval-results.md`를 열어보세요.
   - 1차 테스트 답변으로 비교하려면 관리자 페이지에서 엑셀을 받아 `npm run eval -- --xlsx 파일이름.xlsx`
   - 확인할 것: 말하지 않은 내용이 들어갔는지, 문체가 섞였는지(⚠ 표시), 긴 답변이 잘렸는지
2. **테스트용 번호 준비:** 테스터마다 새 4자리 번호를 주면 분야 선택과 튜토리얼부터 처음 사용자처럼 볼 수 있어요.
3. 테스트가 끝나면 관리자 페이지에서 **전체 엑셀**을 받으세요. 아래 "측정값 보는 법"에 씁니다.

## 테스터에게 부탁할 것

- 질문 **5~10개** 정도 답해보기 (꼬리질문이 나오면 답하거나 "다음 질문으로 넘어가기")
- 목록에서 질문 하나를 골라 답하기, 이미 답한 질문 하나를 다시 답하기
- 일본어 테스터는 일본어로 로그인해서 같은 흐름
- 설정에서 글자 크기와 "소리로 읽어주기"를 한 번씩 켜보기

## 1차 피드백별 확인 항목

| 1차 피드백 | 이번에 바뀐 것 | 테스터에게 물어볼 것 |
|---|---|---|
| 말하지 않은 내용을 지어냄 | 답변 내용만 쓰도록 프롬프트 변경, 짧으면 꼬리질문으로 보완 | 회고록에 내가 하지 않은 말이 있었나요? |
| STT 오류가 그대로 들어감 | 녹음 후 "이렇게 들었어요" 확인·수정 화면, 명백한 오류 자동 수정 | 받아쓰기가 틀린 적이 있었나요? 고치기 쉬웠나요? |
| 글이 문학적·과장됨 / 문체 섞임 | 담백한 "~했다"체 / だ・である체로 통일 | 글이 내 이야기처럼 자연스러웠나요? |
| 긴 답변이 잘림 | 답변 길이에 맞춰 분량 조절 | 길게 말한 내용이 빠짐없이 들어갔나요? |
| 질문 중복 | 중복 질문 교체, 이미 한 이야기와 겹치면 안내 | 같은 이야기를 두 번 하게 된 적이 있었나요? |
| 시간 순서가 섞임 | 질문에 나이대 명시 (예: 40~50대에…) | 어느 시기 이야기를 하면 되는지 분명했나요? |
| 혼자 말하기 힘듦 | 꼬리질문(최대 3개)과 맞장구 | 꼬리질문이 도움이 됐나요, 귀찮았나요? |
| 생성 완료를 모름 | 완성 배너 + 진동 | 회고록이 완성된 걸 바로 알았나요? |
| 질문 번호 없음 | 모든 질문에 번호 | — |
| 일본어 화면의 한국어, 한자 깨짐 | 문구 수정, 일본어 폰트 내장 | (일본어 테스터) 이상한 글자가 보였나요? |
| 분야 복수 선택 | 하나만 고르기 | 고를 분야가 분명했나요? |

## 측정값 보는 법 (질문 수 정하기)

전체 엑셀에 시트가 세 종류 있어요.

- **Overview:** 사람별 평균 녹음 시간, 질문당 평균 체류 시간, 평균 답변 길이
- **Per Question:** 질문별 평균. 오래 걸리거나 답이 짧은 질문을 찾을 때
- **사람별 시트:** 답변 하나하나의 측정값

질문 수 정하는 계산 예시:

- 질문당 평균 체류 시간(꼬리질문 포함)이 **3분**이고, 한 번에 **20분** 정도 쓰게 하고 싶다면 → 한 번에 6~7개
- 공통 50 + 분야 8 = 58문항을 다 하려면 → 약 3시간, 즉 20분씩 9번 정도
- 이 숫자를 보고 문항 수를 줄일지, "하루에 몇 개" 목표를 둘지 정하면 돼요.

"Per Question"에서 평균 답변 길이가 유독 짧은 질문은 답하기 어렵거나 와닿지 않는 질문일 가능성이 커서, 문구를 바꾸거나 빼는 후보예요.
